## Decisions

**D1. Category cap.** `max_categories`: None or int ≥ 2 (validated at construction). `_with_one_hot` passes `max_categories` and `handle_unknown="infrequent_if_exist"` only when set, so default pipelines are unchanged. Unseen levels share the infrequent column only for a column with more than `max_categories` levels; otherwise they are all zeros, as without the cap. Tree models use ordinal codes and are unaffected. Old pickles load with None. `run["max_categories"]` only when set.

**D2. Shadows in place.** `_with_shadows` allocates `np.empty((n, 2p), dtype=X.dtype)`, copies X into the left half, and fills the right half with `np.take(..., out=...)` (joint) or per-column assignment (independent). The random stream and the values are unchanged; tests compare against the old construction.

**D3. Spearman by column blocks.** Blocks hold at most `SPEARMAN_BLOCK_CELLS` (2^18) cells, at least one column (`_column_blocks(width, n_rows)`). A matrix of one block is ranked straight into the array that is centered in place (no preallocation, so a narrow matrix peaks as before, at most about 15 MB); otherwise the ranks of each block are written into one preallocated array. That array is Fortran-ordered, like `rankdata(axis=0)`'s result, and the norms are summed per block of it, so every column sum runs in the same order as on the whole matrix: the values equal the previous implementation bit for bit (tested for 1M x 3, 400k x 65, 300 x 1, 300 x 65, 100 x 129). Measured peaks (tracemalloc, 20000 rows, multiple of the matrix, old -> new): 10 columns 7.3 -> 7.3, 64: 7.2 -> 2.5, 100: 7.1 -> 1.9, 200: 7.1 -> 1.5, 500: 7.1 -> 1.2; the tests require new <= old at every width and new < half of old from 64 columns.

**D4. Training subsample.** `fit(max_samples=None, random_state=None)`, validated like `rank_features` (`_resolve_max_samples`). Rows drawn with `default_rng([random_state, 3])` (distinct from the evaluation draw), sorted; `"within_groups"` uses `_sample_whole_groups`; `"circular"` keeps order (sorted indices). Weights and shuffle labels are sliced; sampled weights summing to zero raise `ValueError`, and so does a sample that misses a class of a classification target (the message names the classes and suggests a larger `max_samples`). Fingerprints use the full data passed. When subsampling was requested the run block records `n_train_rows`, `train_max_samples` (as given, a plain number), `train_random_state` (when given) and `train_rows_sha256` (SHA-256 of the sorted row indices); `ablate()` raises `ValueError` when the report has `train_rows_sha256` and the ranker's rows hash differently (a report without it, or a ranker pickled without `train_rows_`, is not checked). Levels and counts that fit learns (`categorical_levels_`, `missing.train_counts`, `categorical.train_levels`) are those of the sample. `rank_resampled(max_train_samples=)` subsamples each split's training rows with the split's random state; `ConsensusSelector(max_train_samples=)` and CLI `--max-train-samples` pass through.

**D5. Measurement.** Re-run the study's cardinality-1000 and 100k×500 shadow cases with and without the options and record peak RSS in spikes/memory/FINDINGS.md (an "After 1.21" section).
